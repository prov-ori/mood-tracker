# Mood Atlas — личный дневник состояния

Версия 1.2. Готовый исходный проект: ежедневная запись, календарь, графики, профиль, неизменяемые снимки отчётов, печать в PDF, CSV, JSON-копия и восстановление, удаление аккаунта. Интерфейс на русском, есть мобильная адаптация. Шкалы — личные оценки 0–4, не диагностические опросники.

**Сначала настройте проект и выполните тест безопасности. До этого используйте только вымышленные записи.**

## Обновление до 1.2

Миграция Supabase не нужна. После автоматической публикации GitHub → Vercel дождитесь Ready и обновите страницу.

- **Неделя:** выбранный день и шесть дней до него; рядом предыдущие семь дней. Число заполненных дней показано отдельно. Разницы средних — описание наблюдений, не вывод о здоровье. Из сводки можно перейти к отчёту за эти же даты.
- **Отчёты:** поиск по названию и датам в формате ГГГГ-ММ-ДД, сортировка по созданию, концу периода или названию. Поиск не затрагивает черновик нового отчёта. Быстрые периоды: 7, 30, 90 дней и всё время. При смене периода вопросы, название и выбор приватности черновика сохраняются.
- **Копия с паролем:** Профиль → Скачать копию с паролем. Придумайте отдельную длинную парольную фразу (12–128 символов), повторите её, скачайте файл `.mood`. Пароль не отправляется на сервер и не сохраняется приложением. Храните его в менеджере паролей. Восстановить забытый пароль невозможно.
- **Восстановление:** в том же разделе выберите `.mood` или обычный JSON. Для `.mood` введите пароль. После проверки появится подтверждение с количеством записей и заменяемых дат. До подтверждения данные в базе не изменяются. Сначала испытайте восстановление на тестовом аккаунте с вымышленными данными.
- **Напоминание о копии:** на обзоре появляется, если на этом устройстве нет отметки выгрузки либо прошло 30 дней. В localStorage записывается только дата выгрузки для аккаунта, не содержимое дневника. Отметка подтверждает запуск скачивания, а не сохранность файла. При очистке данных браузера дата пропадёт; на другом устройстве она не синхронизируется.

Защищённый файл: AES-256-GCM, уникальные случайные соль и IV, PBKDF2-HMAC-SHA256 (600 000 итераций). Используется Web Crypto API; требуется HTTPS или localhost. Парольная копия шифруется только при ручной выгрузке. Это **не** автоматическое резервирование и **не** сквозное шифрование рабочей базы. CSV и обычный JSON остаются открытым текстом.

Пределы импорта прежние: исходные данные до 20 МБ, 20 000 записей и 500 отчётов. Защищённый файл имеет служебный объём: до 29 МБ. Повторный импорт добавляет отчёты как новые; сначала скачайте текущую копию.

## Обновление уже работающего сайта до 1.1

Повторно выполнять `schema.sql` не нужно: структура базы не меняется. После обновления GitHub дождитесь Ready в Vercel и обновите страницу сайта.

Добавлены разделы «Сон» и «К встрече». Вопросы к встрече можно перенести в новый отчёт; сохраните отчёт, чтобы записка осталась в базе. В новых отчётах личные заметки, события и сведения о препаратах по умолчанию исключены. Для включения отметьте соответствующий флажок. Старые отчёты сохраняют своё содержимое. Полный JSON по-прежнему включает все записи — это резервная копия, а не обезличенный отчёт.

При уходе из изменённой формы появится подтверждение. Автоматического сохранения черновиков нет. Анализ сна использует только заполненные дни; пропуски не заполняются нулями. У показателей нет диагностических порогов.

Перед каждой сборкой Vercel выполняет тесты. Если они падают, исправьте ошибку; не отключайте prebuild ради публикации.

Описание аудита — `AUDIT.md`, идеи дополнений — `ROADMAP.md`.

## 1. Скачайте и распакуйте

Распакуйте `mood-atlas.zip`. Откройте папку `mood-tracker`. Не загружайте ZIP как единственный файл в GitHub: Vercel нужен распакованный код.

В корне должны лежать:

- `package.json` — команды проверки и сборки;
- `vercel.json` — настройки публикации и защитные заголовки;
- `public/` — интерфейс;
- `supabase/schema.sql` — схема базы;
- `supabase/security-test.sql` — тест изоляции пользователей;
- `tests/` — автоматические проверки;
- `scripts/` — сборка без внешних зависимостей.

## 2. Создайте бесплатную базу Supabase

1. Откройте https://supabase.com/dashboard и создайте аккаунт, если его нет.
2. Создайте **New project** на тарифе **Free**. Имя: `mood-atlas`. Для личного использования выберите подходящий вам регион хранения; например, европейский, если это ваш выбор. Сохраните пароль базы в менеджере паролей.
3. Дождитесь готовности проекта.
4. Откройте **SQL Editor → New query**.
5. На компьютере откройте `supabase/schema.sql` текстовым редактором. Скопируйте ВЕСЬ текст в SQL Editor и нажмите **Run**.
6. Ожидается успешное выполнение. Схема предназначена для нового проекта и выполняется один раз. Если появляется `already exists`, не удаляйте таблицы: проверьте, не выполнили ли вы её ранее.
7. В новой вкладке SQL Editor выполните весь `supabase/security-test.sql`. Ожидается **Success**. Он создаёт двух синтетических пользователей внутри транзакции, проверяет изоляцию, запрет изменения отчётов, откат ошибочного импорта и удаление только собственного аккаунта. В конце все тестовые изменения откатываются.
8. Если тест завершился ошибкой, не используйте базу для личных данных. Сохраните текст ошибки без ключей и паролей. В SQL Editor при необходимости выполните `ROLLBACK;`, чтобы закрыть прерванную транзакцию.

### Подключите публичные параметры

В Supabase найдите **Project Settings → API / API Keys** или диалог **Connect**. Названия разделов могут меняться. Нужны:

- **Project URL**, например `https://abcdefgh.supabase.co`;
- **Publishable key** (`sb_publishable_…`). В старых проектах можно использовать **anon public** key.

Откройте `public/config.js` и заполните два поля:

```js
window.MOOD_CONFIG = {
  supabaseUrl: "https://ВАШ_PROJECT_REF.supabase.co",
  allowSignup: false,
  allowRecovery: false,
  supabaseKey: "sb_publishable_ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ"
};
```

Эти параметры предназначены для браузера; они будут видны посетителям. Защита данных обеспечивается входом и RLS-политиками базы, а не секретностью публичного ключа. **Никогда не вставляйте сюда `service_role`, `sb_secret_…`, пароль базы или токен GitHub.**

Этот проект не использует переменные окружения Vercel: публичная конфигурация задаётся именно в `public/config.js`.

### Создайте личный аккаунт без почтовой рассылки

1. Откройте **Authentication → Users → Add user → Create new user**.
2. Введите свой email и уникальный пароль длиной минимум 12 символов. Включите **Auto confirm user / Email confirmed**, если такой переключатель есть.
3. В настройках **Authentication → Sign In / Providers → Email** оставьте вход по email и паролю включённым.
4. Для закрытого личного сайта отключите **Allow new users to sign up** в настройках Authentication. Существующие пользователи продолжат входить.

Создание профиля происходит при первом сохранении имени и часового пояса на сайте. Отсутствие строки в `profiles` сразу после создания пользователя — нормально.

Не отключайте подтверждение email ради открытой регистрации. Личный аккаунт выше создаётся администратором, а публичная регистрация по умолчанию скрыта в интерфейсе.

## 3. Загрузите код в GitHub

1. Войдите в свой личный GitHub: https://github.com.
2. Нажмите **New repository**. Имя, например `mood-atlas`. Выберите **Private**. Для бесплатного Vercel используйте репозиторий личного аккаунта.
3. Создайте репозиторий. Если на пустой странице есть ссылка **uploading an existing file**, нажмите её. В непустом репозитории: **Add file → Upload files**.
4. Перетащите **содержимое** папки `mood-tracker`: `public`, `supabase`, `scripts`, `tests`, `package.json`, `vercel.json`, `README.md`, `VERIFICATION.md`. Сохраните структуру подпапок. Файл `.gitignore` также желательно добавить; он скрыт в некоторых файловых менеджерах.
5. Нажмите **Commit changes**.
6. Проверьте: при открытии репозитория `package.json` и `vercel.json` видны сразу в корне. Если они внутри дополнительной папки `mood-tracker`, либо перенесите содержимое в корень, либо выберите эту папку как Root Directory на следующем шаге.

Исходный код не содержит личных записей. Не добавляйте в репозиторий скачанные JSON, CSV, PDF, пароли и токены.

Альтернатива с Git на компьютере, из папки проекта:

```bash
git init
git add .
git commit -m "Initial Mood Atlas app"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/mood-atlas.git
git push -u origin main
```

Для команд GitHub потребуется авторизация. Не вставляйте пароль или токен в URL команды.

## 4. Опубликуйте на Vercel

1. Откройте https://vercel.com и войдите, например через GitHub.
2. Используйте личный **Hobby** для некоммерческого личного проекта. Не выбирайте платные дополнения.
3. Нажмите **Add New → Project / Import Project**.
4. Подключите нужный GitHub-репозиторий. Предоставьте интеграции доступ только к нему, если интерфейс предлагает выбор.
5. Выберите:

| Параметр | Значение |
| --- | --- |
| Framework Preset | Other |
| Root Directory | Папка, где лежит `package.json`; обычно корень |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Install Command | По умолчанию; сторонних зависимостей нет |
| Node.js | 22.x или 24.x |
| Environment Variables | Не нужны |

6. Нажмите **Deploy**. `vercel.json` уже содержит команду сборки и выходную папку.
7. Дождитесь **Ready**. Откройте стабильный production-адрес проекта вида `https://имя-проекта.vercel.app`. Его достаточно; покупать домен не нужно.
8. Сначала откройте **демоверсию**, чтобы посмотреть интерфейс с вымышленными данными.

После изменения кода через **Commit changes** в основной ветке Vercel автоматически запускает новую публикацию. Дождитесь **Ready** перед проверкой.

## 5. Настройте адрес входа и проверьте сайт

1. В Supabase откройте **Authentication → URL Configuration**.
2. Установите **Site URL**: ваш стабильный production-адрес Vercel.
3. Добавьте этот же точный адрес в **Redirect URLs**. Для локальных экспериментов можно отдельно добавить `http://localhost:3000`. Не разрешайте произвольные чужие адреса.
4. Откройте сайт и войдите личным email и паролем, созданными в Supabase.
5. Откройте **Профиль**: сохраните имя и нужный часовой пояс.
6. Создайте синтетическую запись за сегодня и ещё одну за вчера. Отметьте их как тестовые в заметке.
7. Обновите страницу. В этой вкладке вход должен сохраниться, записи — загрузиться из базы.
8. Откройте календарь, измените тестовую запись и проверьте графики.
9. В **Мои отчёты** выберите период, нажмите **Показать**, затем **Создать и сохранить отчёт**. Откройте его, нажмите **Печать / сохранить PDF**, в окне браузера выберите **Сохранить как PDF**. Рекомендуется альбомная ориентация. Можно выключить колонтитулы браузера.
10. Измените запись дневника. Ранее созданный отчёт должен остаться прежним.
11. В профиле скачайте **JSON** и **CSV**. Откройте их и убедитесь, что в них есть тестовые записи. CSV разделён точкой с запятой и содержит UTF-8 BOM для совместимости с Excel.
12. На отдельном тестовом аккаунте проверьте импорт JSON и открытие восстановленного отчёта. Совпадающие даты заменяются, отчёты добавляются как новые; профиль не импортируется. Повторный импорт добавляет повторные отчёты.
13. Выйдите, войдите вторым тестовым пользователем: записи первого не должны появляться. Дополнительно должен пройти SQL-тест из шага 2 — один интерфейс не доказывает защиту базы.
14. Проверьте мобильный экран и PDF. Если всё работает, удалите тестовые записи и начните личный дневник.

Подсказка: чтобы выбрать произвольный период отчёта, сначала измените обе даты и нажмите **Показать**. Затем задайте название и создайте отчёт.

## 6. Как пользоваться дальше

- **Запись дня:** по одной записи на дату. Каждый из пяти показателей оценивается отдельно. Активация и сниженное настроение не исключают друг друга. Сон — с шагом 15 минут.
- **Календарь:** нажмите на прошедший день для добавления или исправления записи.
- **Обзор:** средние считаются только по заполненным дням. Пропуски видны в покрытии периода и разрывах графиков.
- **Отчёт:** сохраняет копию записей за период, включая заметки и препараты. При исправлении дневника создайте новый отчёт, если нужна актуальная версия.
- **Резервная копия:** хотя бы раз в месяц скачивайте полный JSON и храните его в защищённом месте вне сайта. PDF и CSV не заменяют полную копию с отчётами. Импорт поддерживает до 20 000 записей и 500 отчётов, файл до 20 МБ.
- **Выход:** нажмите «Выйти», особенно на общем устройстве. Дневник не сохраняется автоматически в localStorage. Токены входа находятся в sessionStorage текущей вкладки; обычное закрытие вкладки заканчивает этот локальный сеанс. Некоторые браузеры восстанавливают вкладки вместе с состоянием, поэтому используйте явный выход.
- **Удаление аккаунта:** удаляет пользователя, профиль, записи и отчёты в работающей базе. Нужен ввод `УДАЛИТЬ`. Скачанные файлы и внешние резервные копии удалите отдельно.

## Регистрация и восстановление пароля через email — необязательная настройка

В Supabase встроенный почтовый сервис ограничен и обычно отправляет письма только участникам команды проекта. Для регистрации произвольных пользователей и надёжного сброса пароля нужен собственный SMTP-провайдер. Его бесплатность, квоты и требования к домену зависят от провайдера; этот проект не обещает бесплатную массовую почту.

После настройки SMTP в Authentication и проверки отправки:

1. Если нужна открытая регистрация, разрешите signup в Supabase и задайте `allowSignup: true` в `public/config.js`.
2. Задайте `allowRecovery: true`, чтобы показывать «Забыли пароль?».
3. Сохраните изменения в GitHub и дождитесь публикации Vercel.
4. Проверьте на тестовом email подтверждение регистрации и письмо сброса. После ссылки сброса сайт откроет профиль с формой нового пароля.

Для личного сайта SMTP не обязателен. Если вы забыли пароль без настроенной почты, проверьте возможность административного восстановления в Supabase; не удаляйте пользователя с накопленными записями ради создания нового.

## Telegram

Telegram-бот не включён в эту версию. Сайт полностью работает без него. Нейтральные напоминания и ссылка на форму — разумный следующий шаг после проверки основного дневника. Для этого понадобятся собственный BotFather-токен, webhook на серверной функции и отдельная проверка привязки Telegram к профилю. Токен бота нельзя хранить в `public/config.js` или другом публичном файле. Точное расписание напоминаний нужно выбирать с учётом квот планировщика бесплатного хостинга.

## Приватность и границы версии

Записи хранятся в вашей базе Supabase. Администраторы проекта технически могут читать данные: сквозное шифрование здесь не реализовано. Внешняя аналитика и обращения к ИИ отсутствуют. Выгруженные файлы содержат открытый текст; перед передачей отчёта проверьте его содержание.

Это личный инструмент самонаблюдения, не медицинское устройство, не средство диагностики и не система экстренного мониторинга. Код не предлагает менять лечение. Публичный сервис для других людей потребует отдельной проверки безопасности, правил обработки данных и эксплуатационной надёжности.

Бесплатный Vercel Hobby предназначен для личных некоммерческих проектов и ограничен квотами. Supabase Free имеет ограничения размера и может приостанавливать проекты после неактивности; автоматические резервные копии не входят в этот тариф. Если проект приостановлен, восстановите его в панели Supabase и повторите вход. Доступность «бесплатно и без перерывов навсегда» не гарантируется.

## Локальная проверка для разработчика

Нужны Node.js 22+ и Python 3. В папке проекта:

```bash
npm test
npm run build
npm run dev
```

Затем откройте `http://localhost:3000`. Не открывайте `index.html` двойным щелчком: ES-модули требуют HTTP. Устанавливать npm-пакеты для этой версии не нужно. Сборка копирует только `public/` в `dist/`; SQL и инструкция не публикуются как файлы сайта.

Подробности проведённых проверок и ограничений — в `VERIFICATION.md`.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Войти нельзя, кнопка отключена | Оба поля Supabase в `public/config.js`, новая публикация Ready |
| Failed to fetch / нет связи | Supabase не приостановлен, правильный Project URL, подключение к сети |
| Invalid API key | Используется publishable или anon public key; нет пробелов и лишних кавычек |
| Email not confirmed | Пользователь создан с подтверждённым email; SMTP для открытой регистрации настроен |
| Письмо не приходит | Ограничения встроенной почты; используйте личный аккаунт из Dashboard либо настройте SMTP |
| Таблица не найдена / ошибка RLS | Весь `schema.sql` выполнен в том же проекте, к которому подключён сайт |
| Vercel не видит package.json | Root Directory указывает на папку с `package.json` |
| Отчёт пустой | Нажмите «Показать» после смены периода; нужны записи внутри периода |
| Новый отчёт повторяется после импорта | Импорт добавляет отчёты как новые; удалите ненужный дубликат |
| Данные не загрузились | Нажмите «Повторить загрузку»; не вносите записи до успешной синхронизации |
| SQL уже выполняли | Не запускайте создание схемы повторно и не удаляйте таблицы с данными |
